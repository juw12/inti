# Rubric inti-os-v1

Frozen 2026-11-10 09:30 +07:00, before any code or document of the project was written.
Artifact judged: `dossier.md` (generated by `tools/dossier.py` from the repository: design,
measured evidence with raw log excerpts, comparison with other systems, limitations, code excerpts).

## Hard gates (checked by code, `python build.py gates`; they override the judge)

- G1 One-command clean build: `python build.py` on a clean tree exits 0 and writes `build/inti.img`.
- G2 Boots from its own boot sector (no GRUB, no multiboot) to an interactive shell prompt in QEMU within 20 s.
- G3 In-OS self-test suite prints `SELFTEST: PASS n/n` with n >= 30.
- G4 Fault recovery: every supervised service (console driver, file server) is crashed and hung on purpose, is restarted automatically, the shell still answers afterwards, and the recovery time of each case is measured.
- G5 No ambient authority: every attempt of the capability-less `rogue` program is denied (port I/O, interrupts, physical memory, kernel memory, other tasks, forged capabilities and tokens) and the system stays up.
- G6 Syscall fuzz: at least 1,000,000 random system calls from user space, 0 kernel panics, 0 invariant-check violations.
- G7 Kernel discipline: no heap in the kernel (`alloc` crate absent), every `unsafe` carries a `SAFETY:` comment, kernel is at most 4,000 lines of Rust code (non-blank, non-comment).
- G8 The same disk image boots to the shell prompt in a web browser (v86 under headless Chromium).
- G9 Every number in README.md and docs/ is written by a script into `evidence/claims.json` or carries a source URL; `tools/check_claims.py` passes.

## Soft criteria (council-judged, 1-10)

- C1 Robustness and fault isolation (w=0.30): 4 = boots and runs programs, but a driver or application fault can take the system down or this is untested, 7 = drivers and services run in user mode, injected crashes and hangs are detected and restarted automatically with measured recovery and the kernel survives a syscall fuzz, 10 = what seL4 or MINIX 3 class systems ship: every failure path exercised by automated tests with raw logs, resource exhaustion and supervisor failure handled, invariants machine-checked or proven, no known way for user code to crash the kernel.
- C2 Least-privilege security model (w=0.25): 4 = user/kernel separation only and programs hold ambient authority, 7 = every resource (I/O ports, interrupts, memory, IPC endpoints, task control) is reachable only through explicitly granted capabilities that can only be narrowed and a hostile program is shown being denied, 10 = a complete, minimal, revocable capability system with delegation over IPC, a memory-safe kernel, W^X enforcement and an audited or verified trusted computing base.
- C3 Evidence and honesty of the comparison (w=0.20): 4 = claims of superiority without measurements or sources, 7 = each targeted weakness of mainstream systems is cited to a primary source, each claim about this system is backed by a reproducible script and a raw log, and the comparison names where this system loses, 10 = an independent expert can reproduce every number with one command, finds the limitations section complete and finds no overstated claim anywhere.
- C4 Demo and usability (w=0.15): 4 = builds only for an expert with a custom toolchain, 7 = one-command build and run, an interactive shell with useful commands, a zero-install in-browser demo and real screenshots, 10 = a newcomer understands what makes it different within one minute of opening the demo, guided fault-injection demos, polished documentation, runs on real hardware.
- C5 Code quality and simplicity (w=0.10): 4 = works but is tangled and unsafe code is unexplained, 7 = small readable modules, every unsafe block justified, no dead code, the design document matches the code, 10 = a teaching-quality kernel: minimal trusted computing base, consistent style, invariants stated and checked, auditable in one afternoon.
